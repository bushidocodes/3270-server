# Dialog Tag Language (DTL) tag reference

An alphabetic summary of the z/OS ISPF **Dialog Tag Language (DTL)** tags, with this server's parser (`dtl.py`) support status for each. It mirrors IBM's [Dialog Tag Language (DTL) tags](https://www.ibm.com/docs/en/zos/3.2.0?topic=reference-dialog-tag-language-dtl-tags) *Table 1. Tag summary*, the authoritative source (underlined defaults there are shown as plain text here).

**Support:** ✅ 70 supported · 🟡 26 partial · ❌ 0 unimplemented (of 96 tags).

Status is judged on **attribute coverage**, not just whether the tag renders: ✅ = every documented attribute is honoured (only tags with no attributes, or whose few attributes are all implemented, qualify); 🟡 = the tag renders but one or more attributes are ignored (an attribute parsed as a no-op counts as unimplemented); ❌ = the tag is not parsed. 🟡 and ❌ cells link to a tracking issue.

Legend: **Name** — the tag's full name. **End tag** — whether a closing tag is required. **Attributes** shows each attribute and its value choices (`|` = alternatives; a plain word is the default; `%varname` = a dialog variable). **Tag content** is the tag's text content, or `N/A` if none. `(body text tags)` abbreviates the recurring help-body set (ATTENTION, CAUTION, DD, FIG, INFO, LI, LINES, LP, NT, PD, WARNING, XMP).

## Notes

- Only tags with **no attributes** (or whose handful of attributes are fully honoured) are ✅: `DD`, `DTAFLDD`, `PD`, `VARDCL`, `VARLIST`. Everything that renders but ignores some attribute is 🟡 — the **Parser support** cell names the attributes it reads and the notable ones it ignores.
- Attribute-coverage gaps on rendering tags are tracked by [#122](https://github.com/bushidocodes/3270-server/issues/122) (field attributes), [#123](https://github.com/bushidocodes/3270-server/issues/123) (text/list formatting), [#124](https://github.com/bushidocodes/3270-server/issues/124) (`<attr>`), [#125](https://github.com/bushidocodes/3270-server/issues/125) (panel/area geometry), [#126](https://github.com/bushidocodes/3270-server/issues/126) (action bar/command tables), [#127](https://github.com/bushidocodes/3270-server/issues/127) (messages), [#128](https://github.com/bushidocodes/3270-server/issues/128) (selection), [#129](https://github.com/bushidocodes/3270-server/issues/129) (`<varclass>`/`<checkl>`).
- Some `<lstfld>`/`<lstcol>`/`<lstgrp>` attributes only tune generated ISPF panel sections (`)ATTR`/`)MODEL`/`)PROC`) or are double-byte-only, so they have **no host-display effect** in this display server — they are accepted and ignored by design. See [dtl-lstfld-out-of-scope.md](dtl-lstfld-out-of-scope.md) ([#240](https://github.com/bushidocodes/3270-server/issues/240)).
- **DBCS (double-byte / CJK)** attributes and check types (`FORMAT=DBCS`, `<checki TYPE=DBCS>`, `RULES`, the double-byte `OUTLINE`) are parsed but have no display effect: DBCS is **deferred** because it cannot be verified on this single-byte toolchain. See [dbcs-support-decision.md](dbcs-support-decision.md) ([#135](https://github.com/bushidocodes/3270-server/issues/135)).
- Unimplemented (❌) tags by area: panel-structure [#117](https://github.com/bushidocodes/3270-server/issues/117); small structural tags [#118](https://github.com/bushidocodes/3270-server/issues/118); build/document directives [#119](https://github.com/bushidocodes/3270-server/issues/119); `DL`/`PARML` sub-elements [#120](https://github.com/bushidocodes/3270-server/issues/120). Pre-existing: body/text tags [#52](https://github.com/bushidocodes/3270-server/issues/52), list/table fields [#53](https://github.com/bushidocodes/3270-server/issues/53), assignments [#55](https://github.com/bushidocodes/3270-server/issues/55), `checki` types [#62](https://github.com/bushidocodes/3270-server/issues/62), `lstfld` rows [#67](https://github.com/bushidocodes/3270-server/issues/67).
